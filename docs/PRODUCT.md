# 经纬 GeoAI：应用需求与产品边界

## 产品定位

平台面向“业务需求难转成分析流程、遥感与 GIS 使用门槛高、多源业务数据无法关联、各地专题应用重复建设”的问题，将需求、数据、流程、成果与应用模板连成一条可追溯链路。

“一张图”是可查询、可分析、可持续更新的业务入口。平台应保留源系统的归属、权威台账和更新责任，以标准接口协同，而不是要求将所有业务迁入同一套系统。

## 三条体验主线

### 从一句需求到可执行流程

输入原始需求 → 识别区域、时相与多个业务主题 → 展示数据缺口 → 生成版本化流程 → 确认执行范围 → 执行并保留日志 → 关联空间成果。

流程必须显示实际执行模式。规则辅助规划、示例数据统计与真实模型推理是不同能力，不得混用执行成功标识。对不支持的地区和未知需求，应明确指出条件不足。

### 从分析成果到业务处置

查看本次任务的成果与来源 → 按专题筛选 → 点击空间要素 → 查看属性与核查状态。生产平台后续需增加现场核查任务、证据上传与复核流转；本轮不以“已处置”替代未实现的闭环。

### 从现成组件到复用应用

选择业务组件 → 绑定图层与指标 → 实时预览 → 保存草案 → 发布工作空间版本 → 复用为独立副本。

本轮共享范围是同一本地服务的工作空间，不等于省域开放。发布模板与数据访问授权应分离；生产共享需有身份体系、权限控制、审核及审计。

## 分阶段落地

1. **当前工程版**：本地服务、持久化任务与应用、规则辅助规划、示例空间统计、成果地图、模板发布复用与接口草案。
2. **真实能力试点**：选定有数据和验收口径的单一场景，接入授权影像和解译引擎；验证模型精度、样本、成本、复核流程与交付时效。
3. **跨地区平台化**：租户和角色、数据分级、对象存储与空间数据库、异步计算集群、组件 SDK、服务计量和运营体系。

不能在未接入阶段承诺真实遥感解译、食品安全判断、行政执法认定或面向公网的跨租户共享。
