# V5 遥感生产闭环 · 多专家评审

日期：2026-11-13（Asia/Shanghai）。本文件由架构监督专家记录真实讨论、实施决议和后续复核；建议与计划不作为已实现证据。

## 现状审查

只读检查 `server.py`、`geo_services.py`、`dist/app.js` 与既有API文档，发现V4地图虽已具备真实影像和独立算法，但客户需求入口仍存在两条断开的路径：

- 旧 `/plans`、`/runs` 只能对固定fixture执行示例空间统计。
- 用户数据分析、STAC目录查询和地图成果分别在独立页面；关键词识别到NDVI后仍需跳到实验室手动选择，尚未形成需求到遥感生产的连续任务。

本轮在此基础上增加统一生产任务，不把旧示例流程换名为真实遥感任务，不把目录检索或属性NDVI升级表述为像素解译。

## 第一轮讨论

### 架构与遥感/后端专家

架构师提出最小链路：**自然语言 → 不可变可审查计划 → 后台运行及检索状态 → 有界真实计算 → GIS图层与来源报告**。

计划必须绑定AOI、时相、数据、算子与缺口。目录、属性计算与真实像素处理使用不同execution mode和交付范围；不允许缺数据时静默回退合成源。原始需求及规则解释保留，不能把未知地域默认套为仙桃。

架构师检查当前默认Python环境：numpy、PIL可用，rasterio/GDAL未安装。因此新增真实COG算子需由总体负责人安装并以具备依赖的服务解释器启动；不能仅因依赖计划存在就将能力标为已可用。

### 架构与前端设计专家

前端提出遥感生产作为智能编排的默认工作面：一个需求输入、明确区域/时间/目标、计划摘要与能力说明、任务阶段、成果上图/报告。旧流程和高级配置折叠保留，不制造虚假任务状态。

架构师建议地图抽屉与完整工作页复用同一个ProductionWorkspace任务对象，避免两套状态；减少跳页和需要用户理解的底层概念。计划关键摘要保留区域、时相和实际处理，节点技术详情折叠。

## 第二轮实施决议

### 统一生产任务契约

遥感/后端专家选择 `/api/production/tasks` 作为单一新入口，由后端自动生成计划并启动后台处理；兼容旧API但不混同历史fixture任务。

| 方法 | 拟定接口 | 用途 |
| --- | --- | --- |
| POST | `/api/production/tasks` | 提交需求与显式模式，生成不可变计划并后台运行 |
| GET | `/api/production/tasks` | 当前服务的生产任务历史 |
| GET | `/api/production/tasks/:id` | 计划、运行状态、节点、日志及成果 |
| POST | `/api/production/tasks/:id/cancel` | 取消未结束任务 |
| POST | `/api/production/tasks/:id/retry` | 创建新的重试任务，原记录保留 |
| GET | `/api/production/capabilities` | 当前运行解释器、依赖与可执行能力 |

请求逻辑字段：

```json
{
  "requirement": "分析仙桃验证区两期植被指数变化，形成专题图与来源报告",
  "mode": "sentinel_cog",
  "region": "仙桃市",
  "bbox": [113.3, 30.3, 113.32, 30.32],
  "goal": "ndvi_change",
  "threshold": 0.2,
  "cloud": 40,
  "periods": {
    "before": ["2025-10-01", "2025-10-15"],
    "after": ["2025-11-01", "2025-11-15"]
  }
}
```

以上为评审时约定的逻辑契约，精确枚举、范围和字段以最终实现及接口文档为准，不提前声称样例已被服务接受。

Task应包含：task id、原始需求、mode、创建时间、不可变plan、状态/进度、节点执行与日志、结果/错误、时间和重试来源。Plan应包含version、interpreted区域/AOI/时相/目标、source_bindings、steps及输入输出、executable、blocking_gaps和delivered_scope。成果包含GeoJSON/栅格引用、统计、来源、质量、参数与报告。

### 两种显式计算模式

1. **`sample_pixels`：人工像元验证。** 使用人工构造的两期8×8 red/nir数组与质量mask，实际计算NDVI、差分、阈值和像元Polygon。用于验证生产链路与算术，不代表卫星观测或全市农业实际情况。必须显式选择，并在计划、任务和报告中标识。
2. **`sentinel_cog`：真实Sentinel-2有界像素。** 固定Earth Search检索候选，读取白名单AWS COG red/nir/SCL小窗口，处理为同网格16×16，再掩云和计算NDVI/差分。区域为明确的验证小AOI，不冒充整市分类生产。依赖、网络或数据失败即如实失败，不能切换到人工样本填补。

架构师接受上述有界范围，不要求本轮扩成整市作物分类。真实栅格能力只有在当前服务环境可执行、真实源可读取且结果可复核后才能标记为已实现。

### 前端简化决议

前端提出单CTA“规划并运行”，架构师确认当前公开轻量/本地有界操作不增加额外审批流程。可审查计划不等于强制多一步确认：生成后可随时查看、复制修改，执行始终使用当次不可变快照。

- 输入区一个主任务；模式必须显式，区域/时间自动识别后可查看与修改。
- 计划以范围、时相、方法三条摘要呈现，技术节点折叠。
- executable=false或blocking_gaps时才停在缺口；外网失败显示运行失败和重试，不转嫁为“要求用户补数据”。
- 状态、进度、取消与重试由服务端驱动；页面切换与刷新不制造新任务。
- 完成后突出“实际交付了什么”“成果上图”“查看报告”；目录与像素、样本与真实输入保持明确区别。
- 新参数创建新计划/任务，不改变正在运行的快照。

## 第三轮：最终源码架构与真实像素证据复核

### 复核方法与总体结论

架构师只读复核最终 `production_services.py`、`server.py`、`tests/test_production.py` 和真实任务记录 `output/playwright/v5-public-production.json`；另外以两组独立小数组复算最终阈值比较，未重复下载生产影像或改动产品代码。

**结论：自然语言到可审查计划、后台生产、真实波段计算、GIS网格与来源报告的本轮有界闭环已在服务层形成；未发现剩余源码架构阻断。** 前端仍由总体负责人联调，地图上图、报告展示、操作简化与窄屏结果需实际浏览器验收，不由本节代验。

### 从真实源阻塞到替代源的实际协作

Earth Search在当前环境连接阶段失败，不能仅靠延长目录请求来证明真实生产可用。总体负责人安排架构师验证Microsoft Planetary Computer替代源；架构师实际完成两期STAC、公开SAS、10月景B04/B08/SCL有界窗口与两期产品XML读取，并与遥感工程师即时对齐。

- AOI：`[113.30,30.30,113.31,30.31]`，不是全市。
- 两期候选：2025-10-28与2025-11-27的49RGP场景，均有B04/B08/SCL，原源CRS为EPSG:32649。
- 两期实际产品XML均给出 `BOA_QUANTIFICATION_VALUE=10000`，红光band_id=3、近红外band_id=7的 `BOA_ADD_OFFSET=-1000`。COG头部scale=1/offset=0不能代替产品XML定标。
- SAS仅在内存使用，架构师诊断未输出或写入token及签名URL。诊断证据：`output/diagnostics/planetary-computer-20261113.json`。

遥感工程师随后实施固定PC适配器，并由总体负责人实际调用生产HTTP链路验证，而不是将上述单波段诊断当作整条任务完成。

### 三审发现、修复与独立复算

1. 初版忽略自然语言数字阈值，并将“单期NDVI低于0.1”执行成大于等于默认0.2。架构师用纯函数复现后反馈；遥感工程师增加保守阈值解析、云量与指数阈值分离、body参数优先规则，保存阈值来源及比较运算符。
2. 第二次复核发现两期“小于变化阈值”仍被改为大于等于。已改为保留实际比较运算符，方向下降/上升再按差分方向约束，不把反向变化当命中。
3. 架构师用独立小数组复验：单期NDVI `<0.1` 及两期 `abs(delta)<0.1` 均得到 `[true,false]`，确认低于比较不再反向。
4. 重启恢复初版只改任务终态、节点仍可显示running。已补running节点失败状态与结束时间，避免时间线与任务状态冲突；取消路径原有终态锁保护保持。
5. capabilities中残留AWS描述已同步为Microsoft Planetary Computer公开COG。

遥感工程师报告最终19项生产测试通过，含实际本地GeoTIFF窗口重投影、scale/offset、掩膜、语义方向、状态恢复和不回退样本。此为确定性测试证据；第三方真实访问另按下列任务记录验证。
