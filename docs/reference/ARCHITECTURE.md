# 系统架构与目录职责

本说明对应当前代码整理后的本机工作台。HTTP入口为根目录`server.py`，实现位于`backend/server.py`；该入口、默认端口、API路径及数据目录维持兼容。

## 目录分层

```text
geospatial-AI/
├── server.py                  # 启动入口
├── backend/
│   ├── server.py              # HTTP路由、Workspace装配与进程生命周期
│   ├── paths.py               # 项目资源根路径
│   ├── core/                 # 几何、地图、检索、存储及成果基础服务
│   ├── catalog/              # 数据源、观测资产、算法和工具契约
│   ├── integrations/         # 天地图及本机模型服务适配
│   ├── analysis/             # 原生栅格、指数、年度分类与影像处理
│   ├── agriculture/          # 农业分析、区域成果、作物样本与时序
│   └── workflows/            # 专题、问答、受控执行与行业台账流程
├── dist/                     # 直接提供给浏览器的静态HTML/CSS/JS和vendor资源
├── data_sources/             # 可版本化的来源登记与公开参考元数据
├── map_sources/              # 可版本化的地图和地点参考资料
├── scripts/
│   ├── serve.py              # 选择本项目Python环境并启动
│   ├── check.cjs             # 语法及隔离后端检查入口
│   ├── production/           # 实际数据生产与发布；需显式运行
│   ├── maintenance/          # 数据维护工具；需显式运行
│   └── verification/         # 界面契约及专项检查脚本
├── tests/                    # 隔离单元和HTTP测试
├── examples/                 # 文字需求等非生产输入示例
├── docs/                     # 现行参考、指南、阶段档案
├── data/                     # 本机业务库、私有配置和成果，Git忽略
└── output/                   # 生产中间数据和验收证据，Git忽略
```

`dist/`是当前前端源码与运行资源目录，不是另一个构建工具生成的待提交产物。保持文件名和浏览器资源路径可减少地图、动态模块及既有验证脚本的迁移风险。`backend/paths.py`统一定位项目根目录，运行数据位置仍由数据库路径决定，不依赖当前工作目录推测资源位置。

## 请求与执行链

```mermaid
flowchart LR
    A[一张图：专题或文字需求] --> B[参数与范围校验]
    B --> C[已登记工具与数据契约]
    C --> D[真实读取或校验既有归档]
    D --> E[质量掩膜与计算]
    E --> F[结果、来源与文件版本]
    F --> G[地图、像元核查和下载]
```

结构化专题通过`/api/application-runs`提交，问询通过`/api/assistant/questions`提交。问答、执行记录及底层影像任务分开保存，状态可查询、取消或重试。专题输入在启动前冻结，用户原文与规范化执行输入分别保留。已有归档读取明确标记为复用，不将其耗时称为重新生产影像耗时。

本机Codex桥接提供一般解释和受控规划；固定专题与规则查询可独立执行。模型只产生受验证的数据计划，不执行任意代码、URL或Shell。任务引擎是本机Python服务及后台线程，尚不是分布式作业平台；没有直接接入Google Earth Engine或OpenGE云端算力。

## 数据来源与按需读取

数据目录保存提供方、时空覆盖、类别或波段、许可、认证、适用操作和接入阶段。目录检索、像元读取与算法执行是不同能力；最近一次实际请求证据独立保存，不能由“已登记”推导“已取得数据”。

文章来源登记在`data_sources/agriculture_reference_candidates.json`。运行时将其中四类农业数据作为平台共用来源加载；目录加载只读取元数据，不联网读取像元、不批量预取、不启动分析。`available_years`表示声明收录的年份，`connected_years`表示已有适配的年份，仍需逐次核实具体区域的有效覆盖。

GlobalRice20的2024年产品具备受控COG窗口读取与年度水稻参考面积分析。EARice10、CN_Wheat10、LGISer-CFD及GlobalRice20的2015年数据仍保留接入障碍，不作为可执行输入。新来源应增加提供方适配和契约，并将其状态与实际请求证据分别接入目录。

## 持久化和成果版本

默认数据库为`data/workspace.sqlite3`。使用`--db`时，业务产物和`integrations/`私有配置随数据库父目录保存。SQLite记录不能代替成果文件备份；恢复时需要同时保留原生栅格、图层、统计、来源和清单。

每份计算记录保留范围、年份或实际观测日期、输入场景、质量掩膜、定标、格网、算法与参数。区域成果用`product_sha256`、观测序列用`series_sha256`固定内容版本；下载、地图与像元核查校验同一版本，内容不符返回409。公开行政参考界、用户地块和地图矩形分别声明，不能互换统计母体。

`data_sources/`和`map_sources/`中的公开元数据可随代码分发；`data/`、`output/`、`.venv/`及私有配置不随Git分发。天地图Key由服务端读取，Codex桥接复用本机登录；它们不写入前端、成果包或文档。

## 扩展位置

| 改动 | 主要位置 | 必须验证 |
| --- | --- | --- |
| 新数据来源或资产类型 | `backend/catalog/`、`backend/integrations/`、来源登记 | 固定上游、认证、覆盖、定标/类别、许可与实际读取证据 |
| 新栅格或农业算法 | `backend/analysis/`、`backend/agriculture/` | 原生输入、质量、单位、未知值、空间支持与版本输出 |
| 新业务专题 | `backend/workflows/`、`dist/`场景和表单模块 | 参数校验、真实执行工具、结果恢复、地图与下载 |
| 新HTTP能力 | `backend/server.py`及对应领域服务 | 请求字段、同源限制、错误响应与隔离HTTP测试 |
| 界面交互 | `dist/` | 状态恢复、真实空缺、选区同步、版本固定与响应式阅读 |
