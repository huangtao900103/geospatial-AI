# V3 多专家讨论与架构复核

日期：2026-11-12。记录实际参与的讨论、接口验证和后续代码复核，不将建议当作已经实现的功能。

## 本轮范围决议

总体负责人协调架构师、平台工程师与前端工程师。升级方向为真实公开数据接入、用户 GeoJSON、本地可验证的空间算法与更直观的科技风界面。

本轮采用独立 `dataset + analysis` 接口，不把旧版 plans/runs 的合成示例处理冒充为真实遥感分析。公开天气与影像目录各自保留来源；用户上传分析不自动混入合成 fixture。应用工坊本轮继续明确固定示例源，暂不承诺任意数据源应用发布。

## 第一轮：边界与实施优先级

架构师只读检查了既有 `server.py` 与 `dist/app.js`，向总体负责人提出：

- 数据源成为显式对象，保留来源类型、坐标范围、时间与可追溯标识；不允许无数据时静默回落合成 fixture。
- 优先完成用户 GeoJSON 的真实统计、面积及明确输入条件的算法；公开 Sentinel-2 STAC 实现目录查询，不能等同于影像像素解译。
- 同一界面可以承载多来源，但不同地点、不同时间与不同真实性等级的数据不能隐式混合。
- 天气必须绑定请求地点和更新时间，不能把仙桃天气贴到外地上传数据上。

架构师向前端工程师发出第一轮意见：以短链“选择数据 → 分析 → 上图”组织操作；用公开数据、用户数据、合成示例标签表达来源；用户数据地图使用实际 bbox，避免延续仙桃地名与河流的虚假语境；科技风不牺牲正文与输入区可读性。

## 第二轮：工程师反馈与架构决议

### 平台工程师反馈

平台工程师提出 `geo_services.py` 承担 GeoJSON 校验与算法，用户数据和 fixture 以 source_type 隔离；采用球面环面积、Point Haversine 最近邻与属性 NDVI；固定公开服务白名单，5分钟缓存，失败返回明确错误且无虚构 fallback。

架构师确认可实施，并提出必要门槛：

1. GeoJSON 只支持已经声明和验证的类型/坐标基准；有限数、合法经纬度、闭环、非退化形状、顶点和大小上限均需检查。
2. 跨180度经线、超大跨度、自交与不支持的孔拓扑，应明确拒绝或在成果中明确约束；不静默猜测修复。
3. 面积说明单位、算法与适用范围。若存在相互重叠面，简单求和不是 union 去重面积，必须拒绝或准确命名统计口径。
4. 最近邻仅为地理直线距离，不是路网可达；排除同一要素自身，重复坐标可以合法返回0米，不足2个Point应明确提示。
5. 属性 NDVI 为 `(nir-red)/(nir+red)`，非影像解译。缺失、非有限、负值和零和应分类处理，并报告有效/无效数量，不以0伪装缺失。
6. 上传没有旧版 kind 字段的要素不能被 SCENARIO_KINDS 静默过滤掉。

### 前端工程师反馈

前端工程师提出保留七页并新增“分析实验室”；数据目录统一显示来源类型、时间、bbox和数量；用户/算法数据使用坐标网格与真实 bbox，移除仙桃示意河流地名；实验室显式选择 dataset 和 algorithm，再进入结果地图。

架构师确认该交互方向，并补充：NDVI字段缺失与Point不足时应有可理解说明；公开请求显示地点、时间与错误；上传错误定位几何/字段；结果一键上图且保留算法参数。应用工坊本轮明确固定fixture即可，无需扩大契约。

## 第二轮后：官方资料与真实接口验证反馈

架构师使用官方资料及本机 HTTP 请求验证，而不是仅依赖搜索摘要。

| 来源 | 已核事实 | 实际验证 |
| --- | --- | --- |
| Open-Meteo | forecast/current 是模型资料，输出格点可能偏离请求坐标；支持指定 Asia/Shanghai | 请求 latitude=30.36、longitude=113.45，返回HTTP 200，约2.2秒；格点30.333918、113.42322；本次响应 current_time=2026-11-12T23:15 |
| Earth Search | 官方 `/v1` 公布GET/POST search，包含sentinel-2-l2a集合；目录服务无可用性保证 | 宽查询曾超时；缩至bbox113.2,30.2,113.4,30.4、2025-11-01至11-10、limit=1，HTTP 200约1秒；返回S2B_49RGP_20251107_0_L2A，cloud_cover约99.994% |

以上为当次响应快照，不保证后续请求返回相同天气或首条影像。天气返回格点与请求点应分别留存；高云量目录命中不意味着适合直接解译。失败要显示错误/可重试，不得在“真实数据”标签下展示示例值。

上述验证结果及署名、格点和云量边界已分别反馈给总体负责人、平台工程师和前端工程师。

## 第三轮：最终集成架构复核

- 用户上传合法GeoJSON后可在本机持久化、分析、按真实范围上图；错误几何/坐标不会静默导入。
- 每项分析引用明确dataset及算法参数，结果可追溯；与旧示例任务分开标识。
- 用独立小数据验证数量、带孔面积、最近邻排自身及NDVI边界，说明缺失处理。
- 公开数据实际HTTP成功时显示真实响应；断网/超时显示错误且不伪造；缓存保留抓取时间与地点。
- 外地上传数据不会被仙桃地名、底图、天气或结果选择隐式覆盖。
- 科技风升级仍完成桌面/窄屏、表单、弹窗、加载与错误态检查。

### 代码与服务证据复核结论

**架构结论：在本轮本地数据与算法升级范围内，未发现仍阻断试用的架构问题。** 本轮审阅 `geo_services.py`、`server.py`、最终前端核心逻辑及独立记录 `docs/QA_V3.md`。桌面/窄屏、实际上传表单、真实地图显示、视觉与公开卡片的最终浏览器结果，由总体负责人在 `docs/BROWSER_QA_V3.md` 另行记录，本节不提前宣称通过。

| 门槛 | 已确认的实现与证据 |
| --- | --- |
| 来源隔离 | 用户导入为独立 dataset，旧工作流仍明确使用 fixture；独立 analysis 只读取指定 dataset，不将不同地点或示例要素自动拼入用户数据。输入数据经 deepcopy 后计算，派生属性不污染源。 |
| 版本与哈希 | 数据集为不可变新ID、version=1；SHA-256针对规范化JSON内容计算。分析保存 dataset_id/version/sha256、algorithm_id/version、参数和时间，可按具体输入追溯；不是原文件字节哈希。 |
| 几何与面积 | 仅支持声明的WGS84类型和有界规模；面环闭合、自交、孔内含、MultiPolygon重叠和跨经线均受校验。统计为球面外环减孔、逐要素相加，不是测绘认证或跨要素union。 |
| 最近邻与NDVI | 最近邻只处理Point且排除自身，重复位置可为0；非点数量另行统计。NDVI仅读取非负同尺度属性，缺失/非法/零和为null并统计无效数，全无效返回422；不声称影像像素解译。 |
| 公开请求与缓存 | 仅固定HTTPS服务域名和受控同源跳转；请求体积、时间及返回结构受限。缓存以完整请求URL隔离地点/范围/日期，5分钟内命中保留原fetched_at，并输出cache_age_seconds；失败返回明确502，不生成合成成功结果。 |
| 地点、时间与署名 | 气象同时保留请求点和返回格点及模型时间；STAC保留bbox、日期、云量查询。前端按响应数据渲染地点与单位，附近提供来源署名。天气明确为独立参考点模型资料，不代表当前地图业务范围。 |
| 地图与组件边界 | 地图按所选数据自身坐标投影与适应范围，移除固定仙桃河流地名。应用工坊仍固定本地合成示例，未伪称支持用户数据模板发布。用户内容转义，详情使用服务端唯一顶层feature.id匹配。 |

独立 QA 已记录小数据复算、异常输入及确定性模拟上游的缓存/错误测试，31项自动测试通过。真实天气和STAC请求成功的证据来自第二轮后的架构师/平台工程师实际HTTP访问，不能用模拟上游测试替代。

### 三审发现、讨论与修复

1. **风速单位错配**：后端请求 `wind_speed_unit=ms`，前端初版硬写km/h。已向总体负责人反馈，最终前端改按响应 `units.current` 显示，避免数值与单位不一致。
2. **响应地点标签异步错位**：前端初版用当前表单状态标注已返回天气。已改为响应中的 requested_latitude/requested_longitude，模型格点另行展示；不以之后修改的输入重标旧数据。
3. **用户要素ID优先级**：初版以properties.id优先，可能导致不同顶层ID但相同属性id的要素详情串线。最终渲染与详情改为顶层feature.id优先，并用nullish处理保留数值0。
4. **斜共线退化面**：架构师使用环 `[[113,30],[113.01,30.01],[113.02,30.02],[113,30]]` 只读验证，初版误通过并计算出0.005397公顷。已向平台工程师和总体负责人反馈；工程师增加减原点后的局部米制shoelace退化校验及正反向回归测试。架构师对同一反例复验，现返回 `DEGENERATE_RING`。完整测试复跑结果以工程师/QA最新记录为准。

此轮修复是在已约定的来源隔离、精度与交互门槛内完成，未把真实大模型、影像栅格处理或生产共享扩展为已交付能力。
