> 历史记录：本文保留原阶段的设计、实现和验收口径。路径、数量与能力可能已变化；当前说明见[文档导航](../README.md)、[API参考](../reference/API.md)和[架构参考](../reference/ARCHITECTURE.md)。

日期：2026-11-13。角色：系统架构监督。本轮产品代码只读，仅维护此文档；真实HTTP、浏览器验收与服务集成由主负责人独立完成。

## 1. 本轮交付边界

客户继续在一张图内提问、看答案和空间成果。后台补充统一数据源目录、受限发现、可审阅选源计划及来源绑定，使后续扩展遥感、模型、矢量、业务和物联数据有清晰边界。数据源数量增加不等于算法能力增加；目录记录、网络可访问、读取像素和完成具体分析必须分别证明。

本轮最小实现是整合已有真实适配器及其元数据，增加固定公开STAC目录发现、未执行的数据计划和后续接入草案；不将注册条目、目录命中或接入草案称为已经连接，不宣称已经实现通用多源融合、SAR解译、任意年度耕地分类或标准认证。

总体主体/资产职责、分阶段建设及后续多源执行扩展以主负责人维护的 [MULTISOURCE_ARCHITECTURE.md](MULTISOURCE_ARCHITECTURE.md) 为架构基线；本文侧重实际专家讨论、官方核对、契约门槛及最后源码/证据复验。

**最终源码及API签审：通过，当前无阻断。** 本轮交付统一目录、固定公开发现、未执行计划与真实任务来源引用；不等同于新增所有传感器读取或多源分析能力。主负责人115项检查、49项真实HTTP及追加8次部署语义回归已通过；最后context月度保护补丁另通过17项模块检查与监督者无写入函数复验，证据在末节分别归档。桌面/手机由主负责人实测，监督者没有代验浏览器。

## 2. 两轮实际讨论

### 第一轮：保持客户闭环，后台统一来源

架构师分别向前端与遥感/后端专家提出：客户不填写算法参数；目录须记录时空、模态、分辨率、质量、许可/费用/授权和版本；明确区分目录可发现、数据可读、算法可用及实际执行。

前端建议：答案中只增加折叠“数据依据/选源计划”，展示本次来源、年度、选择理由、阶段和缺口；专业“多源数据”视图承载分类目录、固定STAC检索与选源计划。后台草案、政务、高分、无人机和IoT等未接入项不得标为已连接。

遥感/后端确定最小工程范围：独立 `data_catalog_services.py`，提供源目录、固定公开STAC发现快照、`not_executed`数据计划和端点草案；阶段使用独立能力字段，目录与像素、算法分开。计划推荐与真实已用源分开；仅从成功任务provenance读取`used/execution_evidence`，问答的`plan_ref`由主负责人集成。

### 第二轮：防止错误替代与错误就绪

架构师向两位专家提出并下发门槛：

- 静态实现能力与最近一次实测分开，验证记录带操作、时间、范围和成功/失败/未验证状态；天气、GeoJSON等“像素读取”应不适用，不能因此被误判为未接入。
- `selected`是推荐/候选，不是实际使用。数据计划始终`not_executed`；只有成功任务的provenance能说明某次运行用了什么。引用2021任务不能使2026需求变成已分析；范围、年度或目标不一致时明确缺口或仅列相关历史成果。
- 2026全市耕地面积不能用WorldCover2021替代；S2目录有影像也不意味着已有全市耕地分类器；SAR不能满足光学red/nir NDVI输入；显式source_id也不能绕过模态、年份、质量或授权约束。
- 数据许可、API服务条款和费用分别记录。PC Collection原始license及license链接保留，不能凭公开检索自行宣称免费商用。S1RTC的账号要求、Landsat的目录阶段和未接入适配器如实显示。
- 分辨率按具体波段/资产记录。S2不能所有波段均称10米；S1的10米像元间隔不能直接宣称20×22米分辨能力变成10米；Landsat不同波段/传感器不能统一冒称同一分辨率。
- 固定公开发现受白名单、页数/条数、时空范围、响应大小和超时限制；签名URL只在受控读取时使用，目录/计划/日志不保存token。接入草案不出网，也不改变真实连接状态。

具体冻结字段和最终实现复核见后续章节；以下按实际讨论顺序记录，不把讨论建议直接当作实现验收通过。

遥感/后端第二轮回应已接受上述门槛并落地初修：自然城市解析与多地区冲突、goal语义冲突、NDVI明确时相桥接并调用既有make_plan验证、相对时态保护、签名query拒绝、目录/来源/响应指纹与source_snapshot。上下文来源附加作为lineage_only，不执行新的检索；不匹配任务只放related_existing_result。架构师继续只读复验，发现省域简称与相对当前在lineage_only中的两条漏口，交回同一轮收敛，见末节。

前端第二轮确认并冻结：客户数据依据保持地图内只读dialog；实际使用与推荐来源分栏；非栅格像素维度为不适用，最近验证与实现阶段分开；授权/费用与license分别呈现。架构师针对实际代码提出的lineage_only徽标问题已修：真实成功来源回执显示“已归档实际来源”，不因executable=false误说成缺执行条件；源快照和目录指纹纳入专业技术详情。

## 4. 最小对象契约

### Source：数据源登记

每个来源具有稳定`source_id`、目录版本/元数据指纹、提供者角色、数据模态和产品版本；资产不是由一个“遥感”大类概括。

- `spatial/temporal`：坐标参考、经纬顺序、范围、时间角色（采集时间/产品年度/边界参考年/预报时刻）、时间分辨率与更新说明；集合范围只表示候选覆盖，不是当前AOI的有效观测覆盖率。
- `measurements/assets`：光学波段及单位/定标依据、SAR极化与处理级别、分类类码、矢量schema或IoT观测单位。原生分辨率/像元间隔与显示采样网格分开。
- `quality`：可用质量变量、缺测、云/有效观测判断方式和限制；整景云量只是候选筛选，不能代替AOI像元掩膜。
- `rights/access`：数据license原值/链接/署名、服务条款、费用或未知、账号/密钥要求、授权状态；不保存凭证正文。
- `stages/verification`：注册、目录发现、读取和具体算法支持独立表达；再保存最近实测操作/状态/时间/范围。算法支持必须有明确engine、输入契约、AOI/分辨率/规模限制；已实现不表示任意请求已成功。

### Discovery：发现快照

固定`source_id`与受限bbox/日期/质量条件查询，保存请求参数、提供商/集合、返回Item或记录的固定ID/采集时刻/bbox或footprint/波段资产概要、抓取时间与响应指纹；输出清楚标明目录阶段。最多找到若干场景不代表全AOI、全时段覆盖，也不自动表示red/nir/SCL均可读。本轮归档bbox与资产键概要，未将其冒称精确影像有效覆盖；`response_sha256`是归一化精简Item列表的指纹，不是完整上游响应字节哈希。

### DataPlan：选源计划

保存原需求、解析范围/时段/目标、目录版本、适用候选、拒绝原因、推荐来源、质量/授权/算法缺口及来源快照。字段语义：冻结实现的`selection`为方案，`used`为有执行证据的运行来源，两者不可混用；本轮计划`not_executed:true`，不能出现“已完成解译”的伪状态。

计划的日期、空间、模态、光谱、分辨率、质量、许可授权和算法输入要求先做硬约束，再排序候选。未知应保留未知或待验证，不按零费用、零云或完全覆盖补值。无法满足时清楚列blocking gaps，不能静默替代成另一个年份、地区、测量对象或人工样本。冻结实现使用`status=planned|needs_data`与`not_executed:true`分开描述方案状态和执行事实；不把planned解释为运行已完成。

### RunBinding：实际运行来源

引用已有成功landcover/production/analysis任务的真实provenance，保存具体产品/Item/资产、未签名出处、年份、边界与输入指纹、实际窗口/输出格网/重采样/定标/掩膜、质量与引擎版本。运行绑定必须能回到任务与原始产物；失败/排队任务、仅被推荐的源、仅命中的目录和草案端点不能生成已用证据。

## 6. 后续适配器扩展边界

统一接口可分为`describe / discover / check_access / read / normalize / validate_quality`；不支持的操作明确返回不适用/未实现。源描述与算法契约、读操作及业务任务分离，不能让一个通用URL替代所有能力。

| 适配器 | 可扩展范围 | 注册时仍不能宣称的能力 |
| --- | --- | --- |
| STAC | 集合/Item/资产发现，EO/SAR/Projection/Raster等元数据映射 | 发现不是读取或完成分析 |
| COG/GeoTIFF | 有界窗口读取与元数据、格网校验 | 格式不保证反射率、分类语义或可合法复用 |
| OGC API Features/WFS/GeoJSON | 矢量查询、分页、CRS/字段/范围验证 | 不自动获得授权政务数据，也不是栅格波段 |
| WMS/WMTS/XYZ | 地理配准显示底图/专题图 | 渲染图片不是原始分析像素；不能从底图颜色推算法定面积 |
| WCS/OGC覆盖接口 | 后续coverage裁切与原生/输出格网 | 未实现对应读取/质量引擎前不是可分析接入 |
| 业务REST/数据库 | 业务主键、分类、权属、更新时间与位置关联 | 填一个连接草案不等于台账已同步 |
| SensorThings/IoT/MQTT | 观测、传感器、位置、时间、单位与质量 | 有协议定义不等于已有设备在线或现场实测 |

注册端点/凭证配置、网络连通、鉴权、读取、质量和分析验证应逐项推进。本轮不增加任意URL探测、真实政务/商业凭证或自动付费流程；草案明确`draft_not_connected`且不出网。

## 8. 最终实现复核

### 初版只读复现与回馈

监督者使用临时空数据库直接调用DataCatalogServices，没有发起网络检索或遥感读取，复现并反馈以下问题；仅产生临时诊断数据，未改产品代码。以下问题均已修复并复验：

| 问题 | 初版实际复现 | 最终状态 |
| --- | --- | --- |
| 原文地域被默认值覆盖 | “用遥感统计2021年武汉市全市农田面积”解释为仙桃且可执行；“武汉天气”给仙桃坐标合同 | 已正确解析/阻塞武汉、湖北省/全湖北；不被默认值覆盖 |
| 显式goal覆盖业务指标 | 2026仙桃全市农田面积，加goal=ndvi/小bbox/period后可执行 | GOAL_CONFLICT及执行器校验阻塞，不以小窗替代全市 |
| 选源时段没有进入执行合同 | question=计算NDVI、period=2025年10月，合同body无periods；下游生产解析将使用默认秋季窗 | 已桥接periods并复验真实make_plan仍为2025年10月 |
| 相对年份/当前引用漏口 | 今日/本年/目前曾默认2021；lineage_only曾清掉当前时段 | 已阻塞，当前/2026+历史任务只列related，不进入used |
| 草案可能持久化签名URL | query凭证检查未包括Azure sig/AWS签名参数 | 已以假值复验拒绝已知签名参数，草案存储数0 |
