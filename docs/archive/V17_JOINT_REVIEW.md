# V17 客户应用联合评审

> 历史记录：本文保留原阶段的设计、实现和验收口径。路径、数量与能力可能已变化；当前说明见[文档导航](../README.md)、[API参考](../reference/API.md)和[架构参考](../reference/ARCHITECTURE.md)。

日期：2026-11-14。角色：系统架构、政府农业业务与遥感口径、客户交互、地图视觉。评审目标是在现有一张图与真实执行服务上减少选择成本，改善功能可发现性、结果阅读和地图美感，不增加平台层级，不承诺未接入能力。

本文件由业务/架构评审专家维护。评审仅只读代码与本机HTTP，未调用外发工具、写入正式数据库或修改私有配置；运行代码由各自负责专家实施。

## 第一轮：按四条客户路径检查

| 客户目的 | 既有基础 | 主要体验问题 | 优化原则 |
| --- | --- | --- | --- |
| 找到某个地方 | 地点/坐标/成果统一搜索，中文底图与参考范围 | 地图上存在任务、专题、提问与历史示例等重复入口，首次使用不易分主次 | 保留搜索、范围、上传、图层四项核心操作；定位不等于选为分析范围 |
| 上传台账并查看 | GeoJSON入库、点线面上图、属性点击、图层开关/定位、刷新恢复 | 数据目录、授权接入、专业数据模型混在同一页，客户难区分自己已有数据与待接资源 | “我的上传”先服务现有数据；各来源能力保持准确标记，不把目录可查当成像元可算 |
| 对所选范围分析 | 15个已登记专题，自动组织真实工具执行 | 技术分类和算法卡片平铺，重复“工具已提供”等状态；来源、阈值和公式与基本必填条件同级 | 业务任务优先；保留全部能力，在需要时展开算法/高级参数；范围与日期先行 |
| 查看并复用结果 | 数值、GIS图层、来源、ZIP与单文件、历史复用 | 除耕作地外先展示完整冻结卡片，再结果与大量质量/技术内容；下载入口重复 | 结论和主指标先行，地图与完整成果下载为主动作；条件、来源、过程和单文件按需展开 |

### 必须在客户主视图保留的语义

1. 范围：明确是当前地图框选、某用户数据版本、某次已归档结果，还是固定仙桃参考全市范围。不能将小窗称作全市或全省。
2. 时间：年度分类必须标注2021或2024参考；单景/两景必须显示实际观测日期，不能把请求月度窗口叫作月平均。
3. 数据有效性：缺测与真实零值分开；有效覆盖率不是分类精度。覆盖不足时应直接看到简短提示。
4. 方法边界：光谱线索不是作物细类、产量或灾损认定；FVC是给定端元的估算；地块部分覆盖只统计交集，不能代表整块地。
5. 业务接入：高标准农田、渔政、黄鳝产业链、北斗农机等清单是授权数据与接口准备事项，不能因界面美化显示成已接业务系统。

### 可以收进详情的技术内容

波段编号、SCL/QA位规则、XML定标、参考格网和公式、缓存/窗口字节、哈希指纹、执行器版本、逐步日志与原始JSON。它们仍需保留在来源、处理记录和下载中，客户无需逐项确认。

### 文案与动作统一

减少“真实执行”“工具已提供”“条件已冻结”等密集重复，使用“本次条件”“处理记录”“数据来源与适用范围”等普通业务表述。就绪能力无需逐卡重复标记，只在暂不可用或需补输入时说明原因。主动作优先为“运行分析”“查看地图”“下载成果”；复用条件和单文件下载为次级操作。

## 第二轮：交叉复核与验收要求

已对本轮落地代码进行第二轮只读交叉复核。重点不是算法数量增加，而是原有能力仍可到达、真实年度/范围未被美化隐藏、输入与执行契约未被改变。

| 改动 | 业务/架构复核结果 |
| --- | --- |
| 六个常用专题、八个更多分析、一个专业工具 | 仍覆盖既有十五个专题；固定仙桃能力显示为历史参考，专业光谱入口保留 |
| 来源、阈值和公式按需展开 | 必要范围/日期、产品年度、算法选择、FVC端元及地块数据仍在表单中；NDRE不支持Landsat时仍禁用并阻止提交 |
| 完成后结果先展示、条件移至展开项 | 原始问题、输入范围/日期、参数及复用动作均保留，显示顺序改变不改变任务绑定 |
| 主视图短提示与来源方法详情 | 光谱指标边界、覆盖不足、FVC端元假设、分区交集/重叠、固定历史范围仍可见；技术质量面板未删除 |
| 数据页默认我的数据、四个主标签、设置集中 | 用户数据与目录/像元能力仍区分；时相、分辨率、许可与授权等卡片信息保留，阶段矩阵收起但可展开 |
| 地图减噪与图例 | 客户模式不再默认展示仙桃历史快捷按钮；上传数据显示图层名/要素数，光谱图例保留实际观测，FVC标百分比和端元估算，透明缺测未改 |
| 引导文案与品牌装饰 | 去除英文装饰和泛化承诺，操作指向位置、范围、专题、结果和复用；不再让用户误以为无需明确数据与必要参数 |

第二轮另发现FVC历史结果在执行详情尚未读到时可能误走分区提示分支，已提交给交互专家修复算法身份fallback；用户地块来源用语也建议从“真实地块”改为“上传地块”。这属于显示兜底与事实边界，不改分析算法。

上述为代码与业务语义复核，未将其等同于本轮完整浏览器验收；实际页面、下载和移动端证据由主代理统一记录。

必验路径：

- 搜索地点后仍需明确框选再分析；参考行政界不自动充当法定业务边界。
- 上传GeoJSON自动上图、属性与多图层开关/定位保持可用。
- 常用业务卡能进入原有专题，更多分析与专业光谱指数仍可发现；NDRE不允许Landsat、FVC端元仍须明确、地块统计仍须选真实Polygon/MultiPolygon。
- 使用真实成功结果检查日期、范围、主指标、有效覆盖、完整成果包与单文件下载。
- 历史复用保持原任务绑定，重新分析创建/复用由后端既有规则决定；UI不能凭空产生答案。
- 桌面和390px移动尺寸无横向溢出；外部瓦片临时失败不误报成分析失败。

## 技术边界未变

本轮不增传感器、算法、业务接入或通用模型。只读HTTP核查时，正式服务0.16.0健康，15个专题、23个光谱来源契约、2个农业派生算法存在。光学原生选区上限单边0.05°，上传仍为WGS84 GeoJSON（1–500个要素、2MB），通用模型服务尚待配置。
