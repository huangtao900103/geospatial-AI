# V9 从问题到真实结果：架构监督与执行验收

> 历史记录：本文保留原阶段的设计、实现和验收口径。路径、数量与能力可能已变化；当前说明见[文档导航](../README.md)、[API参考](../reference/API.md)和[架构参考](../reference/ARCHITECTURE.md)。

日期：2026-11-13。角色：系统架构监督。本轮仅维护此文档，产品源码只读；主负责人负责真实数据端到端、模型/环境调查、执行器和地理适配、独立HTTP/浏览器验收与部署。

## 1. 本轮纠偏与交付要求

客户提出问题后，平台应自主完成业务理解、适用数据选择、工具调用、真实数据读取、计算、质量检查、GIS与报告归档，再给答案。满足已支持能力的范围和时相条件时自动开始执行，不停在目录、候选方案或execution_contract JSON，也不要求客户配置波段、供应商或技术流程。

本轮已有可信执行内核：WorldCover2021原生全市分类统计，以及Sentinel-2真实公开波段/质量掩膜/NDVI分析。V8统一目录与选源留痕作为执行过程依据，不能代替调用这些真实内核。缺必要业务条件只作一次合并的简洁追问；空间条件通过地图选区补充后自动继续。不存在的数据、口径或算法不靠人工样本补齐。

规则辅助规划与通用大模型分开声明。没有配置通用LLM时继续使用可验证的业务解析和白名单工具执行，不把模型缺失当作停止已支持分析的理由，也不虚构模型调用。

## 2. 两轮实际专家讨论

### 第一轮：补齐客户执行断点

架构师只读审现有assistant、production、地图及问答后确认：LC已经能真实自动运行；S2虽有执行器，但客户卡禁用、没有范围输入，实际只能转专业工具；data_plan目前仅留合同，不负责调用。

前端提出最小方案：地图两点框选或矩形选区，产生可重选/清除的命名范围chip；只缺AOI时在原问题内给选区入口，保留已识别时相与目标；执行状态来自后端，成功后质量/报告与成果都留在一图。超限不自动裁小窗，也不改成人工样本。

遥感/后端确定统一`workspace.executions`与白名单tool registry：执行服务保存作业、不可变计划、真实工具调用和下游绑定；按已验证计划直接调用LC、production、固定目录和天气函数并等待真实结果，而非执行任意HTTP合同。支持显式用户GeoJSON统计/最近邻时保留用户来源，不冒充遥感分类。

### 第二轮：冻结自动执行、补充条件和证据门槛

架构师向后端提出：固定tool ID映射真实服务函数；冻结原问/AOI/时相/版本；真实子任务、输入输出、状态时间留痕；幂等请求防重复计算；缺条件一次合并追问；S2强制真实COG路径且没有样本回退；质量与观测时刻可见；WC年度/口径及范围保护继续生效；目录工具只在用户请求发现时作为目录结果完成，不能冒称NDVI分析完成。

前端第二轮明确接受：触屏与桌面均可两点选区，确认即新续问原文和空间条件；不用V7的`reference_question_id`引用没有task的needs_data问题。任务开始后AOI冻结，重选只影响新问题。真实steps/tool_calls折叠可查；公开模式、观测时刻与有效率置于答案可见位置。执行器的原生网格升级由主负责人完成，前端按实际新能力更新，不沿用旧16×16说明。

架构师补充：网络超时后重试同一提交应复用request_id与冻结body；用户明确新问或修改条件才创建新请求。旧V7/V8答案与记录保持不可变，新execution引用不重生成旧答案。地图选区完成应自动继续执行，不再加“生成计划后批准/运行”的必经步骤。

以下记录最小契约与实证门槛；实现冻结后补最终复核，不提前把讨论方案当成已完成能力。

## 3. 最小执行契约

### 统一执行记录

后端首轮冻结入口为：

`POST /api/executions {question, request_id?, context?: {bbox?, period?, periods?, dataset_id?, reference_execution_id?}}`

作业必须持久化原问、业务解释、上下文、plan_snapshot或固定plan引用、工具版本和调用参数；活动状态与真实下游任务对应。tool_calls记录实际tool ID、输入、开始/结束、状态、child binding及输出摘要；成功必须有result_ref或真实下游result、质量、GIS/报告与出处。不能只保存一个未调用合同就进入成功态。

冻结初版还支持`context.region`，作业状态为`queued/planning/running/succeeded/needs_data/unsupported/failed/cancelled`。`POST /api/executions/:id/continue`补业务上下文并产生有parent链的新执行；取消/重试也使用真实执行接口。客户assistant接口的`clarification_of`由主负责人桥接，不能直接当作execution的结果引用字段。

来源与执行记录仍可引用V8目录/发现快照，但必须区分推荐和实际使用。`data_plan.not_executed`是旁路计划事实，不能覆盖本轮execution已实际运行的状态；两者各自引用真实任务，不相互冒充。

### 白名单工具与真实调用

| 业务工具 | 必须实际发生的调用 | 成功证据 |
| --- | --- | --- |
| 仙桃年度分类面积/构成/分布 | 复用同源成功LC任务或实际调用landcover服务 | 原生分类统计、质量/覆盖、边界及窗口指纹、GIS栅格和报告 |
| 光学植被指数/变化 | 调用production的公开像素模式，实际发现并读取波段，执行质量与算法 | 场景/资产、真实采集日期、定标/掩膜、有效覆盖、网格/GIS及数值报告 |
| 用户数据空间统计/最近邻 | 明确的用户dataset ID与版本调用已有真实算法 | 用户来源、输入指纹、实际要素与运算结果，不能写卫星识别 |
| 天气模型 | 调用实际已适配预报接口或明确缓存记录 | 请求点/模型格点、预报/获取时间、单位与服务来源，非现场实测 |
| 影像发现 | 固定源实际目录请求 | 命中/空/失败快照及catalog_only；不能作为像素分析成功 |

registry只执行已登记的typed handler，不接受任意URL、代码、shell或模型生成的未验证工具。未来model gateway可生成受约束的业务解释/计划，仍需经过同样的语义、范围、时相、源与工具验证。

### 简洁追问与续跑

缺少必要条件时返回清楚的missing_fields和一句合并说明，保存已经识别的目标、时间和原问。地图选区或业务补充完成后，创建明确的新续问/修订，保留parent链并自动调用工具；它不是历史结果引用。旧needs_data记录不被伪造为已经成功。

用户指定完整范围和时相后无需再次确认技术计划。若仅有一个城市名称，而执行器不能处理该完整区域，不能替换为城市中心代表窗；应说明实际支持尺度并提供图内选区。地理解析产生的范围必须有真实依据与语义，点位缓冲窗不能被叫作行政全域。

## 4. 状态、质量与来源门槛

- request_id幂等：同ID同规范化输入返回同作业；输入冲突明确拒绝。显式重算使用新作业/子任务，并显示重算与复用事实。
- 新原生执行器与旧16×16代表采样任务不可混作同一结果复用；兼容键包含实际算法/网格模式、目标分辨率、AOI/时相、筛选与质量策略等有效输入。旧记录保留，不重新标为原生分析。
- 计划/AOI/时相快照在开始后冻结；刷新、重试、取消和历史恢复不能把旧job改绑最新源或新地图范围。
- 各步骤从真实执行任务更新，不用前端计时模拟进度。取消后终态不能被晚到结果覆盖；共享任务继续与停止等待的语义应向客户说清。
- S2成功不仅要目录命中，还要真实读取、定标、同网格、质量掩膜、实际算法及GIS输出。当前引擎升级后的原生/输出尺度、读取范围与资源上限以冻结源码和实测为准，不沿用未经验证的扩展声明。
- 低有效率遵守实际引擎失败/警告阈值；云量候选筛选不等于AOI有效覆盖。样本、目录、预览和像素分析四者不得混用。
- WC2021×2017参考界不成为当前、月/日、官方法定耕地、播种、高标准农田或作物细分结果。S2指数不是耕地分类、灾损或权属认定。
- 答案由实际result生成；数值、来源年份、采集时刻、范围、质量、工具版本、输入指纹与地图/报告指向同一执行。不得将工具合同或候选场景转述为已分析。
- 外部源或引擎失败保留真实错误和可重试状态，没有虚构数值、人工样本或其他年份回退。

### 原生S2内核与前端初审

监督者已只读核查主负责人新增的`native_raster.py`：版本`2.0-native`；参考末期B04的米制投影原生格网，前期/NIR/SCL最近邻对齐，WGS84选区边缘加密后按像元中心掩膜；统计使用全部选区像元。真实资产先排除DN0等nodata，再应用产品XML定标。有效比例不足10%失败，不足50%保留质量警告；两期均值和差值以共同有效掩膜统计。

原生参考格网产物包括完整分析GeoTIFF（NDVI/差值、共同有效mask、AOI mask等）、3857配准PNG和单一AOI边界GeoJSON。PNG降采样只显示，不参与统计；没有为每个原生像元创建巨大GeoJSON。面积按仿射行列式记录投影面积，明确不是作物/法定地块面积。尺度仍为有界区域，当前上限≤0.05°、1,048,576目标像元；报告说明每期自动选一景，不假称月平均或多景合成。

原生算法版本与旧代表采样`production_services.VERSION=1.0.0`分开。最终代码已直接导入`native_raster.VERSION`进入工具/缓存键，并核对成功结果的`provenance.algorithm_version`及plan/summary/provenance的原生模式；旧16×16或旧原生算法版本不能因同问句被重新标成当前原生结果。主负责人实际E2E与原生TIF离线复算证据见下节，方法审查与独立数值审查分开记录。

前端初审已确认两点框选和返回值接入MapCopilot、AOI快照、冻结请求ID超时重试、真实child步骤、imageOverlay及后台图例；实际观测时刻已补读取`source_details.scenes`。架构师反馈的日期开头完整新问题误加旧reference已改为严格isReferenceFollowup；共享执行中的任务文案已改“关联已有真实任务”，不提前称结果完成。浏览器效果由主负责人独立验证。

主负责人负责真实HTTP、模型/环境、真实数据端到端与桌面/手机浏览器证据；监督者只读复核源码、纯函数业务门槛和本地归档数值，各自证据分开记录。
