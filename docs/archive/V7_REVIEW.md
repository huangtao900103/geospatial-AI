# V7 一张图业务问答：架构讨论、契约与复核

> 历史记录：本文保留原阶段的设计、实现和验收口径。路径、数量与能力可能已变化；当前说明见[文档导航](../README.md)、[API参考](../reference/API.md)和[架构参考](../reference/ARCHITECTURE.md)。

日期：2026-11-13。角色：产品/系统架构监督。产品代码只读；本轮仅维护此文档。

## 1. 交付目标

客户的提问、任务状态、回答、图表、空间结果、来源和下载都留在一张图内。客户使用业务语言，无须选择数据集、算法、影像参数或技术流程。常用问题成为有版本、可复用的业务能力；专业工作台保留为高级入口。

本轮以已经完成真实全域统计的仙桃分类面积能力为主要回答依据，不新增一个凭空生成面积的聊天系统。底层仍是 `landcover_services.py` 的全原生 WorldCover 统计任务及其可复算成果，数值依据见 [V6_REVIEW.md](V6_REVIEW.md)。

**最终源码与API签审：通过，无当前阻断。** 两轮讨论中的语义误路由、错误历史引用、快捷问法字段、分类图例截断和客户旧成果入口均已闭环；没有将未接入地图选区的NDVI接口列为客户已可用。真实浏览器视觉和操作由主负责人另行记录，本结论不预宣告浏览器通过。

## 2. 两轮实际讨论记录

### 第一轮：围绕业务入口收敛

架构师只读审查 V6 的 `app.js`、`map-workspace.js`、`landcover-workspace.js`、后端与验收文档后，向前端、遥感/后端专家分别提出：默认一张图；问答、常用能力、分析记录只切同一抽屉；面积、构成、分布、来源、下载留图内；普通问答复用真实成果，重算才发起任务。

前端专家回应并给出可实现结构：单实例 MapCopilot；三个客户入口“一张图 / 常用能力 / 分析记录”保持同一地图；提问后显示真实任务短卡和结构化回答，自动叠加空间结果；原 area/workflow/lab/apps 等保存在“专业工具”入口。前端要求后端返回统一问答记录、真实状态、答案、地图动作和关联任务，不制作假状态。

### 第二轮：答案绑定、范围和恢复门槛

架构师向两位专家补充并落实以下收敛意见：

- 问答记录 ID 与底层计算 task ID 分开。多个业务问题可以复用同一核算，但每条问题、回答和地图模式应独立保存；历史不能根据“当前最新任务”重写答案。
- 版本键至少包含产品/年份、市界 SHA、方法版本。仅真实成功、版本匹配且必要产物可取的任务可作计算缓存；明确重算新建任务，失败不偷偷以旧结果冒充本次成功。
- 无年份问题可清楚回答 2021 分类基准；当前年度、今年、最新现状、其他年度或区域缺数据时明确不支持。不能将水田/旱地、乡镇拆分、官方耕地保有、播种或高标准农田口径强行映射到 code 40。能力/来源询问中的“当前支持什么”不能被误判为请求当前年度分类。
- `unsupported/failed` 同样留原问、时间与答复；可给“查看2021历史基准”的显式新问题，不能自动更改原问题年份并上图。
- 所有客户文字、历史、错误、来源均作 HTML 转义；旧图层点选须恢复该图层绑定的结果，不能以新缓存任务替换。
- “全部地类分布/构成”使用真实 `classes_url` 并同步分类图例，耕地分布用 `image.url`。只改变显示模式，不从 PNG 重算数值；没有单类掩膜时不承诺任意类别的独立空间筛选。

遥感/后端专家在第二轮明确接受并下发实施契约：统一 questions 入口持久化；`answer_snapshot` 绑定 question ID 和真实 task ID；基础缓存键为产品2021v200、市界SHA和方法版本，实际 `binding.cache_key` 再包含分类窗口 SHA；只有成功且必要产物存在才复用。`context.source_task_id` 或 `reference_question_id` 可锁定旧任务，引用失效为 `needs_data`，不能更换为最新成果。多个问题共享兼容执行；仅“重新核算”新建任务。来源/下载答复使用 `map_effect=none`。快捷问题只保存已答原句与源 question ID，不复制固化数值。树木覆盖与永久水体分别严格对应 code10、code80，不冒充森林资源调查或养殖水面。

架构师确认契约可落地，并追加要求：两个上下文引用冲突应明确拒绝；已经完成的历史只能读取自己的回答快照，只有活动记录随真实任务轮询更新。以上为实际讨论，不把实施承诺提前当作代码与浏览器验收通过。

前端第二轮确认：按 question ID 绑定记录/答案，`image_kind=classes|cropland` 同步 URL 与图例，来源/下载不移动地图。双方另收敛旧书签策略：客户默认旧 `#area/#workflow/#lab` 等进入一张图及助手；只有明确选择“专业工具”才在当前会话开放旧工作台，不将直接访问旧 URL 视为开启专业模式。架构师对已落地初稿提出一个具体接线修正：不支持/失败且没有真实任务的问题不能被自动作为下一次历史基准问题的结果引用；“查看2021历史基准”应是显式的新请求。

## 3. 最小闭环契约

### 业务能力和答案来源

| 客户问题/动作 | 真实依据与要求 |
| --- | --- |
| 仙桃耕地分类面积、公顷/亩 | 关联成功 LC task 的 `summary.cropland_ha/cropland_mu`，不硬编码数值 |
| 各地类面积/构成 | 同一 task 的 `classes[]`；保持 WorldCover 类名和类码；占比以参考界掩膜总面积为分母 |
| 耕地分布/全部地类分布 | 同一 task 的 `image.url/classes_url` 和真实 `boundary`，地图显示模式与图例一致 |
| 数据来源、年份、怎么算、可信度 | 同一 task 的 `provenance/report`；显示 2021 产品、2017 参考界；有效覆盖不称分类精度 |
| 下载已有成果、原生栅格、逐行记录、报告 | 同一 task 的实际产物；本轮已有原生TIFF、逐行计数CSV、完整结果JSON与两幅PNG，不把逐行计数CSV误称为已经包含逐类面积的业务表 |
| 重新计算 | 显式创建新 LC task，显示真实节点/错误/进度；与既有历史分开 |
| 当前/其他年度、省域或未具备口径 | 结构化 unsupported/needs_info；不派发 NDVI 小窗，不自动用仙桃2021替代 |

### 问答记录与执行状态

后端统一负责识别业务问题、确定能力、选择兼容成功任务或创建真实任务、组织结构化答案、保存历史。前端只渲染该契约并控制地图显示，不解析流程参数、不自行计算业务结论。

冻结的客户 API 命名空间为 `/api/assistant`：

| 方法/路径 | 用途 |
| --- | --- |
| `GET /capabilities` | 返回可用业务能力与示例问题 |
| `POST /questions` | `{question, capability_id?, context?}`；自动路由并返回持久问答记录 |
| `GET /questions`、`GET /questions/:id` | 恢复记录与真实执行状态/答案 |
| `POST /questions/:id/cancel`、`/retry` | 取消本问题的等待，或为失败/待补问题创建新问答记录；共享后台核算不因一个等待者取消而中断 |
| `GET /shortcuts`、`POST /shortcuts` | 已回答原句的常用问法，前端提交 `{name,question,source_question_id}`；后端也兼容 `{question_id}` 派生，核对原记录已回答且原句一致，不存数值 |

`context` 可携带 `source_task_id` 或 `reference_question_id`，属于系统内部结果引用，客户不填写。前端冻结接线读取的问答字段为独立 `id/question/capability_id/status/progress/message/logs/created_at`、`binding` 及 `answer`。答案提供 `title/summary/metrics/chart/source_year/boundary_year/warnings/downloads/provenance/result_ref/map_effect`。运行状态以 `processing` 为客户端活动态，终态为 `answered/needs_data/unsupported/failed/cancelled`。后端另保存 `answer_snapshot` 以保证已答历史不改绑；具体源码复核在末节记录。

成功回答成为绑定具体任务和版本的快照。答案显示格式可以调整；来源任务、年份、度量口径和数值不能由前端重新解释。

本轮不要求通用大模型、任意业务分析或新的遥感分类器。规则路由能支持的业务问题必须透明、可测试；无法满足的请求留在图内给出明确答复。

## 4. 验收门槛

| 场景 | 必须观察到的行为 |
| --- | --- |
| 默认入口/刷新 | 一张图为客户入口；没有数据、算法、时间窗参数表单要求客户填写 |
| 首次支持问题 | 自动连接已有能力，创建或复用真实任务；结果完成前不显示成功面积 |
| 缓存复用 | 面积/构成/来源等问题关联同版本真实任务，显示复用事实；不重复下载重算 |
| 明确重算 | 新任务 ID 和真实进度，失败可见；既有答案不被覆盖 |
| 多问题和历史 | 每条原问、回答、时间与关联 task 可恢复；包括失败和不支持的问题 |
| 刷新/关闭抽屉 | 后台任务继续；刷新后恢复同一问答及真实状态；地图实例和图层不因切抽屉重建 |
| 年份和范围 | 2025/2026/当前现状、武汉、省域等不支持请求不被自动改成仙桃2021 |
| 多口径 | 官方耕地、播种、高标准农田、变化或乡镇细分不能被错误回答为 code40 面积 |
| 地图/图表一致 | 耕地/全部分类的图片与图例正确，来源 task 与当前答案相同；历史恢复显示模式 |
| 图内闭环 | 答案、构成、分布、来源、重算和下载不跳转 area/workflow；高级工具需显式进入 |
| 来源和安全 | 固定可见2021产品/2017参考界；用户输入均转义；下载不接受用户任意 URL |
| 手机 | 抽屉、输入、主答案和地图操作可用，无横向溢出，不遮住必要关闭/发送入口 |

### 前端最终静态复核与客户可用边界

只读核对冻结的 `map-copilot.js`、`map-workspace.js`、`app.js` 及 [V7_UI.md](V7_UI.md)：

- 客户主导航三个入口只切同一MapCopilot页签；旧工具URL受客户模式守卫，专业工具明确点击后才在会话内开放。
- 问句/历史/答案/指标/图表类别/日志/错误/来源采用 `esc/escapeText` 后插入HTML；数值从答案读取，下载URL来自后端绑定任务，不接受客户任意URL。
- 来源年份与参考界年份在主答案可见；技术流程/版本在折叠区。`map_effect=none` 的来源/下载不触发新上图或镜头移动。
- `assistant:<question.id>` 独立保存图层，按 `result_ref.task_id` 获取空间成果；切换问题隐藏前一问答层，保留记录以便恢复。`image_kind` 选择真实crop/classes图片；完整类别图例已取消6项截断，永久水体与湿地均可出现；PNG不参与面积统计。
- 新历史基准请求为fresh；已失败/不支持且无task的问题不被自动引用；保存问法提交冻结字段，点击时引用自身源问题。

最终静态审另发现一个旧入口：客户顶栏“成果中心”仍打开旧成果drawer，旧LC详情的报告按钮仍走`go(area)`，会被客户守卫退回overview，无法恢复答案。主负责人已集成最小修正，监督者重新只读确认 `syncCustomerControls()`：客户顶栏按钮改为`client-history`并标“分析记录”；旧drawer与详情关闭；回到客户模式隐藏没有问答绑定的旧owned/示例成果；专业模式仍保留原成果中心。`mount`及`openClientTab`都调用此方法，已闭环，无需旧成果迁移或地图选区。

另经主负责人提出、架构师确认：**后端有接口不等于客户能力已闭环**。当前MapCopilot没有地图选区向`context.bbox`的接线，`vegetation_change`不能在客户常用能力标可用。已只读执行 `capabilities()` 确认其为 `available:false`，说明“待地图选区接入；可在专业工具指定小范围与前后时相分析”，前端按available禁用卡片。带明确bbox/时相的API与专业工具保留；手输NDVI且无bbox的答复也已改为客户地图尚未接入选区、转专业工具指定范围时相。本轮没有扩大选区新功能。
