# 上传数据直接上图验收

日期：2026-11-14。沿用V16正式入口 http://127.0.0.1:8016/ 。本轮修改前端上传、数据目录及地图衔接，未改变遥感算法或后端数据格式。

## 修改后的操作

1. 地图工具栏点击“上传数据”，选择WGS84 GeoJSON并确认图层名称。
2. 点击“上传并显示到地图”；服务器保存后读取完整规范化要素，立即添加地图图层并定位。
3. 点击点、线、面查看原始属性。用户数据最多40项属性全部保留显示，支持中文名称字段。
4. “图层 → 我的数据与成果”可独立开关，并用定位按钮重新显示/定位；刷新恢复最近明确选择的用户数据。
5. “数据 → 我的上传”列出真实用户数据，提供要素数、几何类型、范围、版本、属性/来源预览及“显示到地图”。

## 修复原因

此前上传后仅打开统计专题，没有上图；客户地图的外部来源只接收专业模式选择，导致“查看地图”没有显示数据。本次通过明确的用户数据选择衔接真实GeoJSON图层，不放宽合成示例的来源过滤。另修复导入接口只返回摘要而缓存被当成完整数据的问题，以及选择新无效文件后可能继续导入旧文件的问题。

## 实际验证

使用明确标注“验收、非实际业务”的WGS84文件，包含一个点、一条线、一个面。通过浏览器真实选文件和调用正式接口，完成新上传自动显示、已有数据重新上图、范围定位、属性点击、图层关闭/定位重新打开以及页面刷新恢复。先选合法文件再选择非法JSON时，提示错误且确认按钮禁用，没有误导入旧文件。

桌面截图与390×844移动截图均已目视；移动文档和地图宽度均390px，无横向溢出。刷新后的地图有三个实际矢量要素。三份修改的JS通过`node --check`，浏览器控制台0错误/0警告。已有324条记录逐条SHA256未改变，验收数据单独新增并标注用途。

证据：`output/upload-map/verification.json`；截图：`output/playwright/upload-map-feature-desktop.png`、`upload-map-layers-desktop.png`、`upload-map-myuploads-desktop.png`、`upload-map-mobile.png`。

## 格式边界

目前上传入口仅接收GeoJSON FeatureCollection：1–500个要素、文件≤2MB、WGS84经纬度坐标；后端仍执行几何、属性和坐标复杂度校验。Excel/CSV、Shapefile、GeoTIFF和米制投影坐标尚不支持从该入口直接导入。图层可视化不证明输入业务属性、面积或权属真实。
